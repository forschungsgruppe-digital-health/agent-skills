# Provenance and revision history — `mii-ig-migration`

The dated record of what changed in this skill and what measurement forced it. It lives here rather
than in `SKILL.md` because it is history: an agent activating the skill pays for the body on every
run, and none of the entries below changes what it should do. `SKILL.md`'s *Provenance* section
carries the attribution and the licence, which do not move.

**2026-08-06 — the false "Simplifier is not a scrape target" claim, corrected; the narrative harvest.** This skill stated that the Simplifier guide is client-rendered — "measured HTTP 200, ~56 KB, 52 script markers, no identity metadata in the DOM" — and therefore a human reference at Gate A, not a scrape target. **The measurement was correct and the conclusion was not: it was taken on the PROJECT page and generalised to the GUIDE pages, which are a different URL space and ARE server-rendered.** The cost was concrete: the KDS Consent migration shipped with the **template's starter pages** in place of the module's real German narrative, and nothing in the run flagged it, because a claim of impossibility is never re-checked. Re-measured 2026-08-06 — project page `https://simplifier.net/MedizininformatikInitiative-ModulConsent/` genuinely a client-rendered app shell (the original finding stands **for that URL only**); guide root `https://simplifier.net/guide/miiigmodulconsent/MIIIGModulConsent?version=2026.0.0` **HTTP 200, 24509 bytes, ~3.4 k characters of visible text**, carrying the whole page tree, **23 `href="/guide/…"` links of which 18 are pages**; guide leaf `…/Beschreibung-Modul-Consent?version=2026.0.0` **HTTP 200, 20481 bytes, ~1.4 k characters**, `<h1 id="page-title">` plus the real narrative ("Das MII KDS Modul Consent ist ein Basismodul des Kerndatensatzes (KDS) der Medizininformatik-Initiative (MII)…"). URL shape `…/guide/<guide-key>/<GuideRoot>[/<Page-Slug>]?version=<version>` with **de-punctuated slugs** ("Anwendungsfälle / Informationsmodell" → `AnwendungsflleInformationsmodell`), so slugs are **discovered from the root's links, never constructed**. **What replaced the claim:** spec §2.1.3 now tabulates the two URL spaces with their measurements; §5.1d (numbered §5.1c until the discovery chain below took that slot) is a full narrative-harvest procedure with an explicit order of sources — the **authenticated project download** (`…/$actions/downloading`, measured to require a Simplifier login: anonymous access returns `/login?ReturnUrl=…`, and `$downloads/project.zip`, `/ui/packagedownload/downloadfile`, `/packages/<id>/<v>/download`, `/guide/<key>/$download` were all probed and none is an anonymous archive) **>** the guide harvest **>** nothing, with the **registry package unchanged in role**: resources and identity, no narrative, and the set the harvest is verified against. `scripts/guide-harvest.sh` + `scripts/guide-page-to-md.py` perform the harvest; SKILL.md step 2c is the operating summary. **Verified against the Consent guide:** 18 pages discovered from the root's own links, **18 harvested, 0 skipped**, 14 `narrative` + 4 `artefact-view`, **0 narrative pages short**, 3 assets recorded; pointed at the project page instead, the script exits 2 with `no-page-links:` rather than reporting an empty guide. Three things the real harvest forced that a design would have missed: a page's content region must be isolated by **depth-scanning `<div>`/`</div>`** from `id="preview-content"` (a regex to the next `</div>` truncates at the first nested one and reads as a short page); a guide's page tree contains Simplifier's **rendered artefact views** (Consent's profile page is 239875 characters of generated element tree against a narrative page's ~1400), which are regenerated by the IG Publisher and must not become hand-maintained prose, so they are classified and their conversion losses reported under a separate `generated-view-lossy:` token; and the retention check itself must normalise **both** sides identically — its first version reported five intact German sentences as missing because Markdown moves a link's URL between adjacent words, because `(Projekt)` inside a URL defeated a `[^()]*` pattern, and because a page whose link text *is* a URL had that URL swept from one side only. **The general lesson, now guardrail 9 in `SKILL.md` and guardrail 10 in the spec:** a negative capability finding is only valid for the exact artefact it was measured on, is recorded with its URL/command, date and numbers, and is **never generalised to a sibling** URL or mechanism. This is the second such error in this skill — the first was the claim that the IG Publisher cannot localize page titles, which §5.5 disproved with a working `.po` recipe — which is why the rule is now binding rather than advisory.

**2026-08-06 — the rendered guide made discoverable, and a false negative retired.** §2's `SOURCE_RENDERED_IG_URL` was human-provided, and §5.1 told a reader who had none to give up on the rendering and work from the repository — on the strength of the tier-H measurement that a Simplifier **project** page is client-rendered, generalized into "Simplifier is not scrapeable". The measurement was right about that page and wrong about the platform: the package page, the project's guide listing, the version listing and the guide pages are all **server-rendered**. New **§5.1c** — which took the section number the same day's narrative harvest had held, moving that to **§5.1d**, because a guide is discovered before it is harvested — is the anonymous five-hop chain from an org key and a module name to pinned guide pages — `/organization/<org>/~projects` (23 MII package ids) → `/packages/<id>/latest` (the project slug) → **`/<project>/filterprojectguides`, no tilde** (the `~filterprojectguides` and `~guides` variants return 200 and yield nothing) → `/published-guide/<key>/versions` → `/guide/<key>?version=<v>`, whose root carries the page tree. Three rules come with it: a migration **pins a published, read-only version and records it like the source commit SHA**, because `?version=current` is the live editable project and two runs could silently differ; guide keys and page slugs are **discovered, never constructed** (measured: `miiigmodulconsent` exists, the analogously built `miiigmodulperson` 404s; the renderer de-punctuates *Anwendungsfälle / Informationsmodell* into `AnwendungsflleInformationsmodell`, and the two Consent guides have different GuideRoots); and a guide's version is **not** the module's version, so it is never claimed into the identity ledger (measured: guide 2025.0.1 carries package 2025.0.0). `scripts/simplifier-discover.sh` performs the chain and WARNs at any hop that yields nothing rather than guessing past it — measured end to end on Consent: 23 packages → project `medizininformatikinitiative-modulconsent` → **3** guide keys → 3 pinned versions → **52** page URLs, exit 0; each refusal branch exercised separately (`guide-key-not-published:` on a constructed key, `module-ambiguous:` on 23 candidates, `pinned-version-not-published:` on an absent pin). The gated project download `<project>/$actions/downloading` was re-verified as login-walled on all four query variants and its status is unchanged: an opt-in human step, never a credential mechanism the skill invents. The general rule this restates: **a negative capability finding is measured on the exact artefact it is claimed about** — the same lesson as the retired "the repository carries no narrative" overclaim in §5.1b.1.

**2026-08-06 — the measurement rule stated in both directions, and the sibling skill made a checked precondition.** Two changes, both about a claim this specification makes without the evidence it needs. **(1)** §5.1c.2's rule existed in one direction only — a negative capability finding is measured on the exact artefact it is claimed about — while three shipped defects came from the mirror image, a POSITIVE claim measured on one instance and generalised: the page-title mechanism (§5.5), first "cannot be localized" from a publisher source constant with no build at all and then a mechanism from exactly one build on one publisher version, until the HL7 `multi-lang-test-ig` on 2.0.13 with a deliberately misconfigured `/fr/` supplied a second instance and a controlled negative; "Simplifier is client-rendered, so nothing is extractable", measured on the project page (§2.1.3); and the guide-key shape `data-url="/guide/<key>"`, read on the one module where every key is bare — measured across all 23 MII modules it drops keys silently at exit 0 (consent 3 of 3, **mikrobiologie 2 of 3, person 0 of 3**). In every case the single sample was the benign one, which is the normal case rather than bad luck: the first instance to hand is the reference module, the most regular member of its class. New **§5.1c.2a** states the rule whole and gives the operational test — name the class, measure more than one instance, choose the second as the one most likely to differ (or take the whole set where it is small, or try a controlled negative), record the sample beside the claim, and bound a single-instance claim to that instance instead of widening it silently. The skill-independent form lives in the catalog's `skill-authoring` skill (`references/measurement-rule.md`), because it is an authoring rule and not a FHIR one. **(2)** Step 7 and §7's Definition of Done require `fhir-ig-analysis`' same-module verification and never said how to obtain it, leaving an operator without it to skip the check, hand-wave it or improvise. New **§5.6a** + `scripts/sibling-skill-check.sh` detect the sibling — by its frontmatter `name:`, never by its directory name — and, when it is absent, WARN `sibling-skill-unavailable:` carrying the exact **pinned** `npx skills add …/tree/<ref>` command, with the ref read from the project's own `skills-lock.json` (a recorded `main` additionally raises `pin-not-taken:`, the second independent way to see a pin that never applied). It installs nothing, deliberately: `allowed-tools` grants permission and does not express a dependency — this skill's `Bash(npx:*)` grant, there for the pinned SUSHI/goFSH runs, would equally permit the install — and auto-installing would write to the operator's project as a side effect of an unrelated run, make the run non-hermetic against a version nobody reviewed or recorded, and turn the catalog's deliberate, static-by-design pin into a run-time resolution. Every branch exercised: present → exit 0; absent → exit 1 with the command; name mismatch, `pin-not-taken:`, a `<ref>` placeholder when no lock file records one, `skill-root-undetermined:` when no skills root exists at all (reported as unread, never as absent); bad option exit 2, `--help` exit 0.
